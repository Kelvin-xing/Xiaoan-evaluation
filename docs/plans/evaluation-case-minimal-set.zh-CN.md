> 2026-09-22 更新：本文保留历史 Minimal32 的选集理由，部分旧路由说明已过时。当前 32 案为 96 轮，覆盖 19/20 个 runtime capsule；TC-63 已覆盖 n3a1，缺口为 n5d。现已新增 TC-75（4 轮，自主离婚决策支持，oracle 待人工复核），并另建 Minimal33（33 案／100 轮）。详见 [重复覆盖审查与新增案例](evaluation-minimal32-overlap-audit.zh-HK.md) 和 [Minimal33 清单](evaluation-minimal33.selection.json)。历史 Minimal32 与 Minimal15 未改写。

## 结论

当前目录不是 73 个，而是 `TC-01` 至 `TC-74` 共 74 个 YAML。现有索引还有两处口径问题：正文写“目前测试 68 个”，Emergency/Scenario/Adversarial 的数量合计为 60，且 `TC-61` 至 `TC-74` 没有被纳入旧的合计。本文按实际文件计算，不删除或改写原用例。

在以下覆盖定义下，建议使用 **32 个完整最小集**：

1. 覆盖 6 个 adversarial 红线（RL-01/02/03/04/05/06）；
2. 至少出现 `crisis_sop`、`baseline`，并覆盖当前 oracle 实际使用的 20 个 route/capsule ID；
3. 覆盖紧急风险、未成年人、第三方求助、无障碍/贫困、少数群体、法律程序、执法失效和离家后安全等场景族；
4. 每个保留 case 尽量保留其多轮转折，用于测试 route 从普通支持到危机接管的切换，而不是只取首轮。

这里的“最小”是相对于上述可审计覆盖约束的集合最小，而不是对所有措辞变体逐条保留。若只做每日 smoke，可使用下方 18 个子集。

## 18 个日常 smoke 子集

高频回归可运行：

`TC-01, TC-04, TC-05, TC-09, TC-10, TC-12, TC-15, TC-18, TC-21, TC-23, TC-29, TC-35, TC-37, TC-42, TC-48, TC-53, TC-57, TC-74`

它覆盖三条主 route、全部六条红线和主要高风险路径，但不宣称覆盖全部画像。每次知识库或 router 变更后，先跑这 18 个；每个发布候选版本再跑 32 个完整集。

## 不应静默丢失的缺口与执行规则

- `n3a1`（出具告诫书）和 `n5d`（是否离婚）目前没有任何 case 的 `expected.capsule_ids`，因此不能声称“全 capsule 覆盖”。应新增各 1 个专门 case，或明确它们不属于当前 runtime route。
- `TC-42`、`TC-53` 分别是 RL-02 与 RL-05 的独立边界，不能用相近的法律或情绪 case 静默替代。
- 评测统计必须按 case/turn 记录 route、危机接管、baseline、capsule ground 和 provider operational 状态；provider 失败不能记为质量零分。
- 不要把 74 个 YAML 删除或覆盖成子集。用 manifest/CLI 的显式 case allowlist 运行最小集，保留全量集用于季度回归和新 oracle 校准。
